# Meta API без ризику втратити доступ

Реальний випадок: особистий профіль Facebook заблокували, через тиждень застосунок і токен, створені під цим профілем, отримали **«API access blocked» (код 200) на будь-який запит** — CRM перестала бачити цифри. Токен системного користувача з бізнес-портфоліо в той самий момент працював. Звідси правила.

## 1. Токен — лише системного користувача бізнесу

- Не особистий токен, не токен з Graph API Explorer: вони живуть разом з профілем людини (блок, зміна пароля, звільнення — і все зупиняється).
- business.facebook.com/settings → **Користувачі → Системні користувачі** → створити (роль «Працівник» або «Адміністратор»).
- **Призначити ресурси → Рекламні акаунти**: лише потрібні кабінети. Для читання — «Переглядати ефективність»; «Керувати кампаніями» — лише якщо твоя система справді щось змінює (наприклад, вимикає кампанію після «Так» людини).
- **Створити токен**: застосунок вашого бізнесу, дозволи мінімально потрібні (`ads_read`, `read_insights`; `ads_management` і `business_management` — лише якщо треба). Термін — «ніколи» або 60 днів (Meta зараз радить другий, тоді постав нагадування).
- Токен і App Secret — лише в змінних середовища / менеджері секретів. Не в коді, не в чаті, не в таблиці.

## 2. Кабінети клієнтів — через бізнес, не через профіль

Клієнт дає доступ **бізнес-портфоліо** таргетолога як партнеру, а не особистому профілю. Тоді блок профілю не відрізає кабінет. Якщо кабінету немає в «Призначити ресурси» — його колись давали особисто: попроси клієнта переподати на бізнес.

## 3. Мінімум запитів

- Статистику тягни **раз на день** вранці (за вчора і кілька днів назад — пізні конверсії доїжджають). Цифри «щогодини» майже ніколи не потрібні; якщо треба зараз — ручна кнопка «Оновити».
- Не слати багато запитів одночасно, розносити в часі; при помилках ліміту (код 4, 17, 613, 80004) — зупинитися до наступного дня, не повторювати в циклі.
- Менші періоди й менше полів на запит; у денних інсайтах Meta інколи віддає нулі, коли змішати групи полів (витрати + кліки + дії) — розбий на кілька запитів і зведи за датою.
- Невдалу спробу повтори кілька разів (наприклад, о 5, 6, 7 ранку), далі — до завтра.

## 4. Сторож

Твоя система має сама помічати, що даних немає: «до 8:00 цифри за вчора не прийшли» → одне повідомлення людині. Інакше нулі в звітах помітиш не ти, а клієнт.

## 5. Застосунок і бізнес

- Застосунок — у **верифікованому** бізнес-портфоліо; адміністратор — не одна людина (запасний адміністратор, якому довіряєш).
- developers.facebook.com → дзвіночок (Alerts) і «Required actions»: щорічна **Data Use Checkup** — пропустиш дедлайн, застосунок вимкнуть без продовжень.
- Не тримай один застосунок «на все»: якщо його заблокують, зупиниться все разом.

## Якщо прийшло «API access blocked»

1. Перевір найпростіший запит `GET /me` з цим токеном — якщо теж блок, заблоковано застосунок/токен цілком, а не кабінет.
2. Реклама при цьому **крутиться** — блок стосується лише читання цифр.
3. Подивись: чий це застосунок (профіль заблоковано? застосунок в «Archived»?), алерти в дзвіночку, лист від Meta for Developers.
4. Найшвидше рішення — новий токен системного користувача (кроки 1–2). Старий застосунок оскаржуй окремо, якщо потрібен.
